# 1AGE Universal 3D World Integration Rule — Founder Direction (Nov 23, 2026)

**Non-negotiable: every 1AGE application must remain a genuine, independently functional platform while connecting visibly and coherently to the real approved 1AGE World.**

## Source of truth for the cosmic environment
- Use the **real 1AGE World** cosmic space, approved rotating Earth, orbital ring, atmosphere, existing stars, and exact original controls where World is embedded or integrated. The approved web reference is `1AGEthe3rd/1age-world-web`, `66ead0e5d68fe78370c07f67e515e2a6e2d1c9c0`.
- **Never substitute** randomly placed dots for the original sky, a placeholder ico-sphere for the World Earth, generic 3D rooms, a fake galaxy, invented planets or a disconnected scene simply to mark an app "3D".
- If astronomical accuracy is explicitly required, use a traceable real star catalog and licensed textures/astronomical data from authoritative sources. The existing World star visuals are authentic *to the approved World scene*; their correspondence to a scientific catalog has **not** been independently verified.
- Do **not** overwrite the restored World Godot export, six platforms, Earth, ring, sky, look, movement or gamepad.

## Each app retains its own purpose and existing work
- Cash: balance, activity, approved Cash earning/spending and Stripe account/payment backend belong to Cash, not to a generic World imitation.
- Page: existing 3D orbital social profiles, identity and discovery must remain functional, connected to the shared environment; Page is not a walkable FPS clone.
- Space/HQ1: preserve realistic neighborhoods, property listings and verified-vs-conceptual flags; link/portal to World.
- Games/NNB: preserve existing independently branded gameplay, routes and equipment, while connecting to World/HQ1 as appropriate.
- Exchange, Quest, Store, Blog and other apps: keep their own real 3D functions and independently hosted interfaces. Do not turn them into iframe-only placeholders if real original functionality exists.
- Never delete existing work to make an application appear "integrated". Shared World visuals **supplement**, not replace, app-specific built functionality.

## Safe immediate integration for Cash
The editable Godot source for the approved production World export (`world_build0082.tscn`) was not found in the inspected GitHub repos. Until safely recovered, **embed the actual deployed World runtime** (`https://1age.world/?platform=cash`) as the environment. Keep the Cash-native authenticated account/ledger/payments interface in an accessible foreground layer with a distinctive 3D holographic presentation; *do not* create an alternative synthetic globe, starfield, or flight stage.

The iframe is cross-origin. A link and embedded runtime are not proof that World can read Cash balances, that it implements a Cash venue, or that its stars match astronomical observations. Do not expose Cash credentials or transaction state to the World frame via query parameters or postMessage.

The real World runtime owns the World gamepad and scene. Do not add a duplicate synthetic joystick or controller layer. The Cash interface can use safe touch/keyboard accessible overlays without intercepting original World controls. Any future native gamepad-to-Cash-menu bridge must be built against a verified, consented versioned interface.

## Publication
Work only on protected draft PRs. Provide actual browser rendering of the **original World runtime** with the Cash overlay. Clearly report if Godot cannot load inside a browser/iframe and do not silently substitute another environment. Obtain founder's approval for changes and a separate explicit permission for enabling real financial transactions.

**Design acceptance:** a visitor immediately recognizes the original 1AGE World, its real rotating Earth and original cosmic scene while also finding actual Cash functionality in the Cash platform. No generic fake globe or stars.
