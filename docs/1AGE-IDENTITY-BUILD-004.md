# Identity Build 004 — Cash browser integration (staging)
Official keycloak-js 26.2.5, bundled locally at build time, served through a single explicit SDK route. Browser auth enabled only by AUTH_BROWSER_CLIENT_ID=1age-cash. No stored access/refresh tokens, no secrets in JS, no token messages to the World iframe. PKCE S256 and standard flow. The exact redirect and logout URI is the staging HTTPS origin followed by /; web origin is that exact origin without trailing slash. Never use wildcard redirects. The browser signs in only on explicit action; after reload a user may need to select Sign in again (Keycloak SSO can reuse its session). Third-party cookie status iframe disabled; refresh failure clears local auth. Cash backend validates issuer, signature, audience, short lifetime, authorized party and Keycloak Bearer token type when browser client is configured.
 
## Staging gates
Build command: npm install --omit=dev --no-audit --no-fund && npm run build:identity. Keep test checkout and redemption false, catalog empty, no live credentials. Staging domain not yet assigned; set Keycloak exact root and logout URLs and web origin once assigned. Realm test user only, public registration closed. Verify mapper cash-api in access token, not ID token; token lifespan at most 15 minutes; check actual browser login/logout, reload, distinct user account isolation and database persistence, API rejects unauthorized access, schema and TLS, World renders. Admin MFA, removal of temporary admin and previously exposed DB credential rotation remain security gates before opening access. Do not change public DNS or release to production. No World asset or iframe modification.
